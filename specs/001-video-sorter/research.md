# Research: Sorter

Ресёрч 2026-09-28 (веб, актуальные версии). Формат: решение → почему → альтернативы → риски.

## R1. Воспроизведение видео на карте

- **Decision**: `<video muted autoplay loop>` в WebView2. Источник — свой URI-протокол Tauri `media://` с ручной
  обработкой `Range` (читаем только запрошенный кусок файла). Если `<video>` не смог (событие `error`/нет кадров
  за 1,5 с) — карта переходит в «плёночный» режим: кадры проявки сменяются каждые 400 мс, `Ctrl+O` открывает
  файл в системном плеере (у пользователя MPC-HC).
- **Why**: WebView2 без установок играет MP4 H.264/AAC и WebM VP9/AV1. HEVC — только при установленном
  HEVC Video Extensions, MKV/AVI/MOV демуксер Chromium не читает. Тестовая колода — mp4; телефонные ролики
  (`VID2022…`) могут быть HEVC — запасной путь обязателен. Штатный asset-протокол Tauri на больших файлах
  перечитывает файл при каждой перемотке (tauri#6375, #4133).
- **Alternatives**: локальный HTTP-сервер на 127.0.0.1 (лишний сокет, противоречит духу SC-007); перекодирование
  при проявке (долго, место на диске) — отклонены.
- **Замер 2026-09-28** (T019, сигнатуры `avc1`/`hvc1` в mp4): `G:\vk videos` — 181 H.264, 6 HEVC (≈ 3 %,
  пример `1645360412776.mp4`). Плёночный режим нужен, но редок; проверять на этих 6 файлах.

## R2. Кадры плёнки и сведения о файле

- **Decision**: Windows Media Foundation через crate `windows` 0.62: `IMFSourceReader` → seek → `RGB32` → кадр
  уменьшается до 320 px по длинной стороне и пишется JPEG q80 в кэш (crate `image`). Оттуда же длительность,
  размер кадра и поворот. Дата съёмки: из имени файла (`VIDyyyyMMddHHmmss`, 13-значный unix ms), иначе `mtime`.
- **Why**: без внешнего exe, portable; MF на Win11 читает MP4/H.264, MKV и HEVC (если есть кодек) — шире, чем
  `<video>`, поэтому плёнка будет и у тех карт, что не играют.
- **Alternatives**: `ffmpeg-sidecar` (+~100 МБ, LGPL-обязательства), `ffmpeg-next` со статикой (тяжёлая сборка) —
  отложены; добавить sidecar, только если MF не справится с реальной колодой.
- **Risk**: файлы, которые MF не читает, → `stage = broken`, карта раскладывается без плёнки.

## R3. Подсказки

- **Decision**: эмбеддинги DINOv2-small (Apache-2.0, ONNX fp16 ≈ 43 МБ) через crate `ort` 2.0.0-rc.13 с
  DirectML (любая DX12-видеокарта) и откатом на CPU. Вектор карты — среднее по 4 центральным кадрам плёнки,
  L2-норма. Подсказка — kNN (k = 3, косинус) по примерам стопок, см. data-model.md.
- **Why**: DINOv2 создан для kNN-классификации по примерам и лучше CLIP на «похожести сцен»; подсказки не требуют
  текстовых меток — стопки учатся на самих видео. Модель маленькая.
- **Поставка**: `onnxruntime.dll`, `DirectML.dll` и модель вшиты в exe (`include_bytes!`) и при первом запуске
  распаковываются в `%APPDATA%\com.stillmvd.sorter\runtime\`; `ort` в режиме `load-dynamic`. Так соблюдается
  «один exe» (+≈ 70 МБ к размеру).
- **Alternatives**: CLIP ViT-B/32 (вдвое тяжелее, нужен только для текстовых запросов — их нет); `candle`
  (GPU только CUDA); MobileNetV3 (слабо для сцен).
- **Risk**: `ort` 2.x формально rc — закрепить версию в `Cargo.lock`.

## R4. Корзина

- **Decision**: crate `trash` 5.2: `trash::delete` для хода в «Корзину»; при отмене — `os_limited::list()` →
  найти элемент по исходному пути и времени удаления → `restore_all([item])`. Если по исходному пути уже есть
  файл — ход не забирается, ошибка `FILE_IN_THE_WAY` объясняет, какой файл мешает.
- **Risk**: пользователь очистил корзину → ход не забирается, в журнале «файла в корзине нет».

## R5. Слежение за колодой и стопками

- **Decision**: `notify` 8.2 + `notify-debouncer-full` (тишина 1,5 с). Готовность файла — успешное открытие
  без `FILE_SHARE_WRITE`; `ERROR_SHARING_VIOLATION` → повтор с нарастающей паузой до 60 с. Так же следим за
  первым уровнем стола (новые/переименованные/удалённые папки → `piles://changed`). Плюс полная пересверка
  при запуске (события ОС могут теряться).

## R6. Перемещение между дисками

- **Decision**: свой код без зависимостей: `fs::rename`; при `ERROR_NOT_SAME_DEVICE` (17) — копия во временное
  имя `.<имя>.sorter-part` в целевой папке → `sync_all` → сверка размера → `rename` во итоговое имя →
  удаление исходника. Каждый шаг отмечается в `MoveItem.step` (data-model.md), так что сбой на любом шаге
  восстановим.
- **Alternatives**: `fs_extra::move_file` (без контроля fsync/сверки) — отклонено.

## R7. Интерфейс и каркас

- **Decision**: стек и каркас Demo Prep (Tauri 2, React 19, Vite 7, Tailwind 4, TypeScript, pnpm), заголовок окна —
  `../Echo Studio/src/components/layout/Titlebar.tsx` + `WindowControls.tsx`, шрифты Kockers Sans из
  `C:\Users\stillmvd\Fonts`. Состояние — React без внешних менеджеров (одна страница, два режима, три оверлея).
  Хранилище — `rusqlite` (bundled), как в Demo Prep; фронт в SQLite напрямую не ходит.
- **Why**: переиспользование (принцип VI), одинаковый стиль (принцип IV).

## R8. Скорость смены карт (SC-002)

- **Decision**: держать в DOM три `<video>`: текущая, следующая (предзагружена, на паузе), предыдущая (для
  Ctrl+Z). Ход меняет роли элементов, а не `src`. Перенос файла идёт после смены карты — интерфейс не ждёт диска;
  при ошибке карта возвращается с сообщением.
- **Risk**: предзагруженный файл открыт WebView2 → перенос на Windows может упасть на блокировке. Решение: перед
  переносом снять `src` у элемента этой карты (он уже не показывается) и повторить попытку до 3 раз по 100 мс.
