# Feature Specification: Sorter — раскладка видео по папкам

**Feature Branch**: `001-video-sorter`

**Created**: 2026-09-28

**Status**: Draft

**Input**: User description: "Sorter — десктопное Windows-приложение для раскладки локальных видео по папкам: колода (папка-источник) и стол (корневая папка, подпапки — стопки), проявка (раскадровки, сведения, подсказки в фоне), режимы «Колода» и «Стол», экраны первого запуска, проявки, стопок, журнала и «колода пуста», локальные подсказки, только перемещение с журналом и отменой. Дизайн — .planning/DESIGN.md."

## Clarifications

### Session 2026-09-28

- Q: Что делать с ненужными видео — удалять прямо из Sorter? → A: Встроенная стопка «Корзина» (клавиша Delete): файл уходит в корзину Windows, ход забирается как обычный.
- Q: Брать ли видео из подпапок колоды? → A: Только верхний уровень папки-источника.
- Q: Как новые видео попадают в колоду? → A: Сразу: Sorter следит за папкой колоды, новые файлы проявляются и встают в колоду без перезапуска.
- Q: Звук видео по умолчанию? → A: Выключен, M включает, выбор запоминается.
- Q: Будет ли перетаскивание мышью? → A: Да, внутри Sorter: карту или отмеченные плёнки — на стопку, мимо стопки — карта возвращается.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Разложить колоду по одной карте (Priority: P1)

Пользователь выбирает папку с неразобранными видео (колода) и папку, внутри которой лежат целевые папки (стол).
Видео по одному появляются в центре экрана и сразу играют. Поняв, о чём видео, пользователь нажимает клавишу
стопки — файл уезжает в нужную папку, на экране сразу следующее видео. Ошибся — Ctrl+Z, видео возвращается.
Не уверен — Tab отправляет видео в конец колоды.

**Why this priority**: это и есть замена нынешнему процессу «открыть в плеере → закрыть → найти глазами →
перетащить → промахнуться». Одно это уже решает задачу.

**Independent Test**: выбрать копию `G:\vk videos` и пустую папку стола с 3 подпапками, разложить 20 видео
только клавишами, забрать 2 хода, убедиться, что файлы лежат ровно там, куда их положили.

**Acceptance Scenarios**:

1. **Given** первый запуск, **When** пользователь выбирает колоду и стол, **Then** видит число видео в колоде
   и список стопок из подпапок стола, и может начать раскладку.
2. **Given** карта на экране и у стопки «Музыка» клавиша 2, **When** пользователь жмёт 2, **Then** файл
   перемещается в папку «Музыка», счётчик стопки растёт на 1, на экране следующая карта, в «Последнем ходе» —
   этот файл и стопка.
3. **Given** только что сделан ход, **When** пользователь жмёт Ctrl+Z, **Then** файл возвращается в колоду под
   исходным именем и снова показывается на экране.
4. **Given** карта на экране, **When** пользователь начинает печатать «му», **Then** стопки фильтруются по
   названию, Enter кладёт карту в первую подходящую.
5. **Given** карта на экране, **When** пользователь жмёт Tab, **Then** карта уходит в конец колоды без
   перемещения файла.
6. **Given** в стопке уже есть файл с таким же именем, **When** карта кладётся туда, **Then** существующий файл
   не затирается, новый получает имя с суффиксом, пользователь видит это в «Последнем ходе».
7. **Given** горизонтальное видео после вертикального, **When** оно становится верхней картой, **Then** карта
   плавно поворачивается и принимает горизонтальную форму.

### User Story 2 - Проявка: понять видео по раскадровке (Priority: P2)

При первом открытии колоды приложение в фоне «проявляет» её: для каждого видео готовит плёнку из 6–8 кадров и
сведения (дата, длина, размер, разрешение, ориентация). Под картой видна плёнка — многое понятно без просмотра;
стрелки ← → двигают по кадрам. Раскладывать можно сразу, не дожидаясь конца проявки.

**Why this priority**: раскадровка сокращает время решения с «досмотреть» до «взглянуть» — главное ускорение
после клавиш.

**Independent Test**: открыть колоду из 187 видео, наблюдать экран проявки, через 10 секунд перейти к колоде и
увидеть плёнку у первых карт; дождаться конца и убедиться, что плёнки есть у всех.

**Acceptance Scenarios**:

1. **Given** колода открыта впервые, **When** идёт проявка, **Then** экран показывает прогресс «N из M»,
   плёнки проявляются по мере готовности, есть «Начать раскладывать» и «Пауза».
2. **Given** проявка не закончена, **When** пользователь раскладывает, **Then** карты с готовой плёнкой идут
   первыми, работа не подтормаживает.
3. **Given** колода уже проявлялась, **When** приложение запускается снова, **Then** готовые плёнки не
   пересчитываются, проявляются только новые видео.
4. **Given** видео не читается (битый файл), **When** проявка доходит до него, **Then** карта помечается
   «не удалось проявить», её всё равно можно разложить или пропустить.

### User Story 3 - Стол: разложить пачку (Priority: P3)

Пользователь переключается в режим «Стол» и видит контактный лист — плёнки многих видео сразу. Наведение
проигрывает видео, клик/Shift отмечает несколько. Клавиша стопки или поиск + Enter раскладывает всю пачку одним
ходом; Shift+Enter создаёт новую стопку из набранного текста и кладёт пачку туда.

**Why this priority**: похожие видео (серия с одного дня) раскладываются за одно нажатие вместо десятка.

**Independent Test**: отметить 5 плёнок, нажать клавишу стопки — все 5 файлов в папке; Ctrl+Z возвращает все 5
одним ходом.

**Acceptance Scenarios**:

1. **Given** стол открыт, **When** пользователь отмечает 4 плёнки и печатает «жив», **Then** остаётся видна
   подходящая стопка, остальные гаснут; Enter кладёт все 4 туда.
2. **Given** отмечены плёнки, **When** пользователь печатает название, которого нет, и жмёт Shift+Enter,
   **Then** в столе создаётся папка с этим названием, пачка кладётся в неё, стопка появляется в ряду.
3. **Given** пачка разложена, **When** пользователь жмёт Ctrl+Z, **Then** возвращаются все файлы этого хода.
4. **Given** отмечены плёнки, **When** пользователь жмёт Esc, **Then** отметки снимаются.

---

### User Story 4 - Подсказки стопки (Priority: P4)

Приложение сравнивает кадры новой карты с картами, уже лежащими в стопках, и подсказывает: «Просится в стопку
Животные, 81%», рядом вторая по вероятности. Enter кладёт карту в подсказанную стопку. Чем больше разложено,
тем точнее; до этого подсказка честно показывает «учится · N примеров». Подсказки можно выключить.

**Why this priority**: превращает раскладку в подтверждение Enter'ом, но без P1–P3 бесполезна.

**Independent Test**: разложить вручную по 5 видео в 3 стопки, затем пройти 20 карт и посчитать, как часто
первая подсказка совпала с выбором.

**Acceptance Scenarios**:

1. **Given** в стопках меньше порога примеров, **When** показывается карта, **Then** подсказки нет или она
   помечена «учится · N примеров», Enter ничего не делает без подсказки.
2. **Given** подсказка «Животные 81%», **When** пользователь жмёт Enter, **Then** карта ложится в «Животные».
3. **Given** пользователь положил карту не в подсказанную стопку, **When** следующая похожая карта,
   **Then** подсказка учитывает этот выбор.
4. **Given** подсказки выключены на первом запуске, **When** пользователь раскладывает, **Then** блока
   подсказки нет, остальное работает.
5. **Given** на столе вместе отмечены карты, **When** они похожи на одну стопку, **Then** над пачкой видна
   общая подсказка.

---

### User Story 5 - Стопки и клавиши (Priority: P5)

Экран «Стопки и клавиши»: все стопки стола карточками с числом карт, клавиша каждой стопки меняется нажатием,
папку можно переименовать, можно создать новую стопку. Клавиши по умолчанию раздаются по порядку 1–9, затем
Q, W, E, R, T, Y…

**Why this priority**: удобство при 10–30 стопках; базовые клавиши работают и без этого экрана.

**Independent Test**: переназначить клавишу стопки, переименовать папку, создать новую — изменения видны в
проводнике и в ряду стопок колоды.

**Acceptance Scenarios**:

1. **Given** экран стопок, **When** пользователь выбирает «сменить клавишу» и жмёт F, **Then** стопка получает
   F; если F была у другой стопки, та остаётся без клавиши и это видно.
2. **Given** экран стопок, **When** пользователь переименовывает стопку, **Then** папка на диске
   переименована, журнал ходов продолжает указывать на неё правильно.
3. **Given** в стол извне добавили папку, **When** приложение запускается или пользователь обновляет стопки,
   **Then** новая стопка появляется с первой свободной клавишей.

---

### User Story 6 - Журнал ходов и итоги (Priority: P6)

Журнал показывает все ходы: время, файл, куда положен, как (клавиша, подсказка, поиск, стол). Любой ход можно
забрать, есть «Забрать всё за сегодня». Когда колода пуста — экран итогов: сколько разложено, по каким стопкам.

**Why this priority**: страховка и чувство завершённости; Ctrl+Z последнего хода уже есть в P1.

**Independent Test**: сделать 10 ходов, забрать 3-й из журнала — вернулся ровно этот файл; разложить колоду
до конца — показан экран итогов.

**Acceptance Scenarios**:

1. **Given** журнал, **When** пользователь забирает не последний ход, **Then** возвращается только этот файл.
2. **Given** файл хода вручную удалён или перемещён из стопки, **When** пользователь пытается забрать ход,
   **Then** приложение объясняет, что файла на месте нет, и ничего не ломает.
3. **Given** последняя карта разложена, **Then** показывается экран «Колода пуста» с итогами и кнопками
   «Открыть журнал» и «Открыть стол в проводнике».

### Edge Cases

- В колоде появились новые видео, пока приложение открыто — они проявляются и встают в конец колоды сразу;
  файл, который ещё копируется, берётся только когда запись закончена.
- Файл исчез из колоды извне, пока лежал в ней — карта тихо убирается из колоды.
- Корзина Windows отключена или диск её не поддерживает — ход в «Корзину» не выполняется, пользователь видит
  причину; файл остаётся в колоде.
- Видео в колоде открыто другой программой (заблокировано) — ход не выполняется, карта остаётся, пользователь
  видит понятную причину и может попробовать снова.
- Колода и стол на разных дисках — перенос копированием со сверкой; при нехватке места ход отменяется
  до удаления исходника.
- Приложение закрыли или выключили питание посреди хода — при следующем запуске незавершённый ход доводится
  или откатывается, ни один файл не теряется и не дублируется.
- Стол пуст (нет подпапок) — ряд стопок пустой с приглашением создать стопку печатью названия.
- Папку стопки удалили извне — стопка исчезает из ряда, ходы в неё в журнале помечены «папки нет».
- Колода совпадает со столом или лежит внутри него — первый запуск не даёт так выбрать и объясняет почему.
- В колоде есть не-видео файлы — они не попадают в колоду и не трогаются.
- Очень длинное видео (десятки минут) — плёнка равномерно по длине, проигрывание с начала, перемотка по кадрам.
- Имя стопки с запрещёнными для Windows символами — при создании/переименовании пользователь видит, какие
  символы нельзя.

## Requirements *(mandatory)*

### Functional Requirements

**Колода, стол, ходы**

- **FR-001**: Пользователь MUST выбрать колоду и стол системным диалогом выбора папки; выбор запоминается между
  запусками и меняется в настройках.
- **FR-002**: Колода MUST включать видеофайлы только верхнего уровня папки-источника; вложенные папки и не-видео
  не трогаются.
- **FR-003**: Стопки MUST соответствовать подпапкам первого уровня стола.
- **FR-004**: Каждый ход MUST записываться в журнал на диске до перемещения файла и отмечаться завершённым после.
- **FR-005**: Система MUST только перемещать файлы; удаление допускается лишь для исходника после проверенной
  копии при переносе между дисками. Единственный путь «удалить» — встроенная стопка «Корзина».
- **FR-005a**: Встроенная стопка «Корзина» (клавиша Delete, всегда последняя в ряду) MUST отправлять файл в
  корзину Windows; ход в неё записывается в журнал и забирается так же, как любой другой (файл восстанавливается
  из корзины на исходное место).
- **FR-006**: При совпадении имени в стопке система MUST сохранить оба файла, добавив суффикс к новому.
- **FR-007**: Незавершённые ходы MUST при запуске доводиться до конца или откатываться по журналу.
- **FR-008**: Пользователь MUST иметь возможность забрать последний ход (Ctrl+Z) и любой ход из журнала;
  ход пачкой забирается целиком.

**Режим «Колода»**

- **FR-009**: Верхняя карта MUST показывать видео, которое начинает играть сразу, без звука; пауза — Пробел,
  M — включить/выключить звук (выбор запоминается).
- **FR-010**: Форма карты MUST повторять ориентацию видео; смена ориентации между картами — плавный поворот,
  при системной настройке уменьшения движения — мгновенно.
- **FR-011**: Под картой MUST показываться плёнка-раскадровка и сведения о файле; ← → переходят по кадрам.
- **FR-012**: Клавиша стопки MUST класть карту в стопку одним нажатием; печать MUST фильтровать стопки,
  Enter — класть в первую подходящую (при пустом поиске — в подсказанную).
- **FR-012a**: Карту MUST можно перетащить мышью на стопку (в колоде — верхнюю карту, на столе — все отмеченные
  плёнки): стопка под курсором подсвечивается, отпускание мимо стопки возвращает карту на место без хода.
- **FR-013**: Tab MUST отправлять карту в конец колоды без перемещения файла.
- **FR-014**: Следующая карта MUST появляться без видимого ожидания после хода.
- **FR-015**: Блок «Последний ход» MUST показывать файл, стопку и итоговое имя (если был суффикс).

**Проявка**

- **FR-016**: Система MUST в фоне готовить для каждого видео плёнку из 6–8 кадров, равномерно по длине, и
  сведения: дата, длина, размер, разрешение, ориентация.
- **FR-017**: Проявка MUST сохраняться между запусками; повторно обрабатываются только новые или изменённые файлы.
- **FR-017a**: Система MUST следить за папкой колоды во время работы: новые видео проявляются и встают в конец
  колоды без перезапуска, файл берётся только после окончания записи; исчезнувшие файлы убираются из колоды.
- **FR-018**: Раскладка MUST быть доступна во время проявки; экран проявки показывает прогресс, паузу и
  переход к раскладке.
- **FR-019**: Нечитаемое видео MUST помечаться и не останавливать проявку остальных.

**Режим «Стол»**

- **FR-020**: Стол MUST показывать плёнки нескольких видео сразу с прокруткой, наведение — проигрывание
  выбранного видео.
- **FR-021**: Клик MUST отмечать плёнку, Shift+клик — диапазон, Esc — снимать отметки.
- **FR-022**: Клавиша стопки или поиск + Enter MUST класть все отмеченные одним ходом; Shift+Enter —
  создавать стопку из набранного текста и класть туда.

**Подсказки**

- **FR-023**: Система MUST подсказывать до двух стопок с оценкой уверенности на основе сходства кадров карты
  с картами в стопках, считая всё на этом компьютере.
- **FR-024**: Подсказки MUST учитывать каждый новый ход; до набора минимума примеров показывается
  «учится · N примеров».
- **FR-025**: Подсказки MUST выключаться на первом запуске и в настройках; без них всё остальное работает.
- **FR-026**: Для пачки на столе MUST показываться общая подсказка, если отмеченные похожи на одну стопку.

**Стопки, журнал, итоги**

- **FR-027**: Экран стопок MUST позволять менять клавишу, переименовывать папку и создавать стопку; клавиши по
  умолчанию — 1–9, затем Q W E R T Y U I O P.
- **FR-028**: Журнал MUST показывать время, файл, стопку и способ хода; забрать можно любой ход и «всё за
  сегодня».
- **FR-029**: После последней карты MUST показываться экран итогов.
- **FR-030**: Ошибки ходов MUST объясняться человеческим языком с причиной и следующим шагом.
- **FR-031**: Настройки MUST содержать тему (системная/тёмная/светлая), смену колоды и стола, подсказки,
  очистку кэша проявки.

### Key Entities

- **Колода**: папка-источник; список карт, порядок, позиция.
- **Карта**: одно видео колоды — путь, имя, сведения (дата, длина, размер, разрешение, ориентация), плёнка,
  состояние (в колоде, отложена в конец, разложена, не проявлена, ошибка).
- **Стол**: корневая папка стопок.
- **Стопка**: подпапка стола — название, клавиша, число карт, примеры для подсказок.
- **Ход**: одно действие раскладки — время, карты (одна или пачка), откуда, куда, итоговые имена, способ,
  состояние (начат, завершён, забран, сбой).
- **Подсказка**: для карты или пачки — до двух стопок с уверенностью и число примеров, на которых она основана.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Разложить 187 видео тестовой колоды можно не больше чем за 25 минут без мыши (≈ 8 с на видео
  против нынешних ≈ 30–40 с).
- **SC-002**: После хода следующая карта готова к просмотру за 0,3 с или быстрее в 95 % случаев.
- **SC-003**: 0 потерянных или перезаписанных файлов в тесте: 200 ходов, 50 отмен, 5 принудительных закрытий
  посреди хода, перенос между дисками.
- **SC-004**: Проявка первых 20 карт занимает не больше 15 с; раскладка возможна не позднее чем через 5 с
  после старта проявки.
- **SC-005**: После 40 разложенных видео первая подсказка совпадает с выбором пользователя не реже чем в 60 %
  случаев на тестовой колоде.
- **SC-006**: Новый пользователь проходит первый запуск и кладёт первую карту меньше чем за 1 минуту без подсказок
  со стороны.
- **SC-007**: Sorter не отправляет никуда ни файлы, ни сведения о них; сам он в сеть не ходит (кроме проверки обновлений из фичи 003, которая выключается в настройках). Фоновая сеть WebView2 отключена флагами; служебное соединение рантайма WebView2 при старте — вне контроля приложения.

## Assumptions

- Пользователь один, работает на своём ПК с Windows 11; видеокарта есть, но подсказки обязаны работать и без неё
  (медленнее).
- Видео — распространённые форматы (mp4, mov, mkv, webm, avi, m4v); прочие файлы игнорируются.
- Стопки — только подпапки первого уровня стола; вложенные деревья вне объёма первой версии.
- Одна пара «колода + стол» активна одновременно; смена — в настройках, проявка хранится для каждой колоды.
- Журнал хранится бессрочно; «Забрать всё за сегодня» — за текущие календарные сутки.
- Интерфейс только на русском; дизайн и слова — по `.planning/DESIGN.md`.
