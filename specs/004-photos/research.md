# Research: Фото

## Декодер

- **Decision**: крейт `image` 0.25 (уже в зависимостях), включить фичи `png`, `webp`, `gif` к `jpeg`.
- **Rationale**: JPEG через zune-jpeg быстрый; `ImageDecoder::exif_metadata()` и `orientation()` дают сырой EXIF
  и поворот для JPEG/PNG/WebP. Для миниатюры 320 px хватает; оригинал карте показывает WebView.
- **Alternatives**: WIC (Windows Imaging Component) — быстрее на 48 Мп за счёт масштабирования DCT, но COM-код
  и отдельный путь поворота; вернуться, если SC-002 или проявка не уложатся.

## EXIF

- **Decision**: свой разбор TIFF IFD из сырых байт: IFD0 `Make` 0x010F, `Model` 0x0110, `DateTime` 0x0132,
  указатель 0x8769 → Exif IFD `DateTimeOriginal` 0x9003. Поворот — `ImageDecoder::orientation()`.
- **Rationale**: 3 ASCII-тега и один указатель — ~50 строк, тестируются на байтах; новый крейт не нужен
  (конституция VI).
- **Alternatives**: `kamadak-exif` — надёжно, но лишняя зависимость ради трёх полей.

## Дата снимка

- **Decision**: `taken_from` = `exif` (DateTimeOriginal, иначе DateTime) → `name` (`deck::taken_from_name`:
  13-значная метка в мс, `IMG_`/`PXL_`/`VID`) → `file` (дата изменения).
- **Rationale**: в `G:\vk photos` EXIF с датой у 94 из 266, но имена всех файлов — метки времени в мс; этот разбор
  уже работает для видео. Карта пишет «Снято», «Дата из имени» или «Дата файла — даты съёмки в файле нет».

## Показ на карте

- **Decision**: `<img>` с адресом протокола `media`; поворот по EXIF делает Chromium (`image-orientation:
  from-image` по умолчанию), GIF анимируется сам. Следующая карта: `new Image()` + `decode()` заранее.
- **Rationale**: без копий в кэше и без своей отрисовки. `media.rs` для картинок отдаёт файл целиком: сейчас
  файлы > 16 МБ без заголовка `Range` отдаются частью — для `<img>` это обрезанная картинка.

## Миниатюра и вектор подсказок

- **Decision**: проявка фото пишет `cache/<id>/0.jpg` (320 px по длинной стороне, после поворота), `frames = 1`.
  `hints::card_frames` для фото берёт `0.jpg`; вектор — DINOv2 по одному кадру, то же пространство, что у видео.
- **Rationale**: общие примеры фото и видео (FR-013), плитки стола и «Последний ход» используют ту же миниатюру.

## Серии

- **Decision**: `series.rs` — проход по фото колоды (`in_deck`/`deferred`, `solo = 0`, проявленные), сортировка по
  `taken_at`; ребро между соседями, если `taken_at` отличается ≤ 10 с и pHash (64 бит) расходится на
  `SERIES_MIN < ham ≤ SERIES_HAM`. Серия — цепочка из ≥ 2 снимков. Для `taken_from = file` порог строже
  (`SERIES_HAM_FILE`). `series_id` = id первого по времени снимка; лучший — максимум `sharp × √пиксели`.
- **Стартовые пороги**: `SERIES_MIN` = 2 (почти одинаковые — это копия, её ловят дубли), `SERIES_HAM` = 18,
  `SERIES_HAM_FILE` = 10. Подбираются на `G:\sorter-test\photos` (SC-003) — тест `series_on_set`.
- **Rationale**: на `G:\vk photos` по имени подряд ≤ 10 с только две пары: ham 32 (разные кадры — не серия)
  и ham 0 (одинаковые — дубль). Реальные серии проверяются синтетикой: сдвиг 1–4 %, яркость ±8 %, шаг 1–3 с.
- **Резкость**: дисперсия лапласиана на серой миниатюре 320 px.
- **Разбить**: `card.solo = 1` у всех снимков серии; ход и отмена `solo` не трогают.

## Ход серии

- **Decision**: `moves::place_series`: отмеченные (или все, если отметок нет) — `move_with` в стопку; остальные при
  «в Корзину» — второй `move_with` в Корзину с тем же `group_id`; при «оставить» — не двигаются и становятся
  обычными картами (серия пересчитывается). Ошибка второго хода откатывает первый (как `replace_copy`).
- **Rationale**: журнал, отмена группой и восстановление после сбоя уже есть.

## Дубли фото

- **Decision**: `dupes::files` берёт медиа, отпечаток фото — `print::print_photo`: `frames` = [pHash после среза
  полей], `stills` = [миниатюра] → смысловой вектор; `duration_ms = 0`, звука нет. `near::compare` для фото:
  pHash ham ≤ 8 → `same` (уверенность `100 − 5·ham`), иначе смысл ≥ 0.9 → `crop`. Сравнение только внутри типа
  (по расширению). Пары, у которых оба снимка в одной серии, не показываются (`dupes_for`, `groups`).
- **Rationale**: тот же `fingerprint`/`dupe`, та же плашка и экран; сравнение «видео ↔ фото» бессмысленно (FR-015).

## Фильтр типа

- **Decision**: настройка `kind_filter` (`all` | `video` | `photo`), параметр `kind` у `deck_window`, счётчики
  `deck::counts_by_kind`. Сегмент в шапке колоды и стола; экран «Колода пуста» при пустом типе предлагает
  переключиться, если остался другой тип.
